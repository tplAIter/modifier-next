# Next App Router modifier

This independently authored MIT content replaces the React Router SPA with a Next App Router application. It preserves the reusable React data/schema, item models and UI component bytes. This is a separate modifier, not a React setting, enrolled native root, installed composition or fallback runtime.

The backend contract is bounded cancellable JSON CRUD against an explicitly configured server-only HTTP endpoint. No database, credentials or authentication service is bundled. Missing backend configuration produces an unavailable result; an empty successful collection is never invented. Server pages/routes are separate from interactive client forms. Next/server-only16.3.8/0.0.1 and React19.3.0 use the genuine Bun1.4.2 lock, unchanged after one offline frozen producer check.

The source delivery has two stages. Content and raw payloads are captured first. After actual React and Next content publication, authenticated immutable source subjects bind modifier.manifest.json through the existing closed Modifier schema. That final file is intentionally absent while publication subjects are unavailable; no zero/dummy source pins or caller authority are emitted. See docs/lifecycle.md. Pure parser/render checks cannot certify conversion, update, reversal, native Bun execution or full P13.

## Agent discovery bootstrap

The discovery source is published at commit `29e9819df3c3e4ce170c025b74d895375090e2ea`; check the installed CLI/MCP capability and version before using it because an installed binary or server may predate that source. Use standard MCP `tools/list` capability detection and call `template_discover` only when its exact tool and schema are advertised. The required `task` is a UTF-8 string of 1–4096 bytes; optional fields are `sourceInput`, `projectContext`, `dir`, `language`, `framework`, and `labels` (`group=value`). Bounds are `maxCandidates` 1–256 (default 64), `limit` 1–20 (default 5), and MCP `maxBytes` 2048–32768 (default 16384). Treat responses as bounded descriptive data; `facts.status` is `not-requested`, `empty`, `observed`, or `unavailable`, with errors and diagnostics kept distinct. Invoke only advertised read-only `nextToolCalls` (`template_show` or `graph_exports`) to retrieve exact context, preserving arguments, `expectedDigest`, and source-pin metadata unchanged; retain and report typed refusal/error/unavailable conditions.

Workflow: discover capability, select a returned suggestion, read its exact bounded calls, then use that context for the task; never invent, replace, flatten, or manually reconstruct returned calls.

If MCP discovery is unavailable or reports an error, record the MCP `isError` or protocol error. If an installed binary built from the published discovery source is available and its CLI version/capability check confirms discovery, use the verified read-only fallback `tplaiter template discover --task "..." --dir ./path --json`; omit `--dir` when no project path exists. Otherwise stop and report the unsupported capability. Existing and empty directories are valid observations; respect the output budget. Discovery does not enroll sources, apply changes, run hooks, or grant installation authority; it does not change this modifier's publication or installability status.
